Site facts (the ground truth)

  • Type: static site — plain HTML/CSS/JS. No build step, no framework, no server. This is deliberate: it's why a non-technical PI can maintain it.
  • Repository: github.com/christopherruano/carmody_lab_website (Chris's personal account).
  • Hosting: GitHub Pages, served from the main branch, repository root.
  • Live URL: nme.fas.harvard.edu, set by the CNAME file plus a Harvard FAS DNS record.
  • Deploy: push to main → GitHub Pages rebuilds automatically (~1 min). No manual publish step.
Handoff

The one architectural gotcha

js/main.js is the shared brain of the site. It injects the nav and footer into every page, and also holds the search index (hand-maintained), the slideshow captions, and the research-tab / load-more behavior.

!

Nav, footer, and search are centralized here — not per-page. Any editor (human or AI) needs to know this. It's documented in CLAUDE.md, which Claude Code loads automatically.

Handoff

Access — chosen approach

✦

Decision: add Rachel as an Admin. The repo stays on Chris's account; Rachel gets full control without touching hosting or DNS.

On github.com/christopherruano/carmody_lab_website → Settings → Collaborators and teams → Add people → add Rachel with the Admin role. Add one backup lab member as Admin too, so access never rests on a single person.

A full ownership transfer was considered and declined — it would have required a coordinated DNS change with Harvard FAS. Revisit only if Chris's account is ever closed. The Claude/Anthropic account Rachel uses for Claude Code is separate from GitHub and should be her own.

Handoff

Handoff checklist

  • Add Rachel (+ one backup) as Admin collaborators on the repo.
  • Confirm GitHub Pages is green (Settings → Pages; custom domain reads nme.fas.harvard.edu, HTTPS enforced).
  • Clone the repo fresh onto Rachel's / the lab machine.
  • Install Claude Code there; sign in with a lab-owned Claude account; confirm claude launches in the repo folder.
  • Do one live test edit together end-to-end (add a dummy news item, publish, see it, then remove it). The most valuable part of the handoff.
  • Record the Harvard FAS / HEB IT contact for any future DNS issues.
