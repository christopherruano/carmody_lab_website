Website Handoff Notes

This document gives the technical facts and the decisions for the handoff of nme.fas.harvard.edu. It is a companion to the Maintenance Guide.

Handoff

Facts about the website

  • Type: a static website. It uses only HTML, CSS, and JavaScript. It has no build step, no framework, and no server. This is on purpose. A non-technical person can maintain it.
  • Repository: github.com/christopherruano/carmody_lab_website. It is on Chris's personal account.
  • Hosting: GitHub Pages. It serves the main branch from the root folder.
  • Address: nme.fas.harvard.edu. The CNAME file and a Harvard FAS DNS record set this address.
  • Deploy: push to the main branch. GitHub Pages then rebuilds the website in about 1 minute. There is no manual publish step.
Handoff

One important point about the structure

The file js/main.js is the center of the website. It puts the navigation menu and the footer on each page. It also holds the search index, the slideshow captions, and the code for the research tabs and the news button.

!

The menu, the footer, and the search are in this one file. They are not on each page. Each editor, a person or an AI, must know this fact. The file CLAUDE.md gives this information. Claude Code reads CLAUDE.md automatically.

Handoff

Access: the chosen method

✦

Decision: make Rachel an Admin. The repository stays on Chris's account. Rachel gets full control. This does not change the hosting or the DNS.

Open github.com/christopherruano/carmody_lab_website. Go to Settings. Go to Collaborators and teams. Select Add people. Add Rachel with the Admin role. Add one more lab member as an Admin also. Then the access does not depend on one person.

A full transfer of ownership was an option. We did not choose it. A transfer needs a DNS change with Harvard FAS. Do a transfer only if a person closes Chris's account. The Claude account for Claude Code is separate from GitHub. Rachel must have her own Claude account.

Handoff

Handoff checklist

  • Add Rachel and one more person as Admins on the repository.
  • Make sure GitHub Pages is on. Open Settings, then Pages. The custom domain must read nme.fas.harvard.edu. HTTPS must be on.
  • Copy the repository to Rachel's computer or the lab computer.
  • Install Claude Code on that computer. Sign in with a lab Claude account. Make sure the claude command starts in the website folder.
  • Do one test change together, from start to end. Add a test news item. Publish it. Look at the website. Then remove the test item. This step is the most useful part of the handoff.
  • Write down the contact for Harvard FAS or HEB IT, for DNS problems.

The content bot (forms)

A GitHub Action lets Rachel or Amar make the 4 most common changes from a form, with no terminal: add a news item, add a lab member, remove a lab member, and change text on a page.

  • The forms are in .github/ISSUE_TEMPLATE/. The workflow is .github/workflows/content-bot.yml. The generators are in scripts/.
  • A form makes an issue. The workflow runs the correct generator, edits the files, and opens a pull request. Nothing goes live until a person merges the pull request.
  • The generators are deterministic. They do not use an AI. There is no API key and no cost for each use.
  • The workflow runs only for a repository collaborator. It never publishes on its own.
  • One repository setting must stay on: Settings → Actions → General → "Allow GitHub Actions to create and approve pull requests." It is on now.
  • Claude Code does all other changes. To add a "publication" form later, copy the pattern (a form, a scripts/add-*.mjs, and a branch in the workflow router). CLAUDE.md has the details.
