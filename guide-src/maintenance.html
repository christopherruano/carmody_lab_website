Website Maintenance Guide

How to keep nme.fas.harvard.edu up to date — written so you never need to touch code.

Live site: nme.fas.harvard.edu Built by Christopher Ruaño Updated July 2026
Section 01

The big picture

You do not need to know how to code. The idea is simple: you open a tool called Claude Code, tell it in plain English what you want changed, it makes the change, and it publishes it to the live website.

  • The website's files are stored on GitHub (a service that keeps files and a full history of every change).
  • The public site is nme.fas.harvard.edu.
  • When a change is saved and uploaded to GitHub, the live site updates automatically within about a minute. There's no "publish" button and no web server to log into.
  • Claude Code is an assistant that runs on your computer. You talk to it in a chat window, like texting a very capable assistant sitting at your keyboard.
✦

Nothing you do here can permanently break the site. Every change is saved in GitHub's history and can be undone — see Section 07.

Section 02

One-time setup

You do this section once. After it's done, day-to-day edits take a few minutes.

What you need

  1. A computer (Mac or Windows).
  2. A GitHub account. You've been added as an Admin on the website's repository, so you already have full control. The repository is github.com/christopherruano/carmody_lab_website.
  3. Claude Code installed. Chris or the department's computing support can install this and sign you in with a Claude account. Once installed, you open it from the Terminal app by typing claude and pressing Enter.
✦

Ask whoever sets you up to walk through one news update with you the first time, so you see the whole loop once. After that you'll be comfortable.

The one folder you'll open

The website files live in a folder on your computer (the person who sets you up will make a one-click shortcut). You never open the individual files yourself — you just start Claude Code inside that folder, then type your request.

Section 03

How every edit works

Every single change follows the same three steps:

  1. Tell Claude Code what you want, in plain English (see the recipes below). Be specific — names, dates, and exact wording.
  2. Let it make the change and show you. It's fine to ask "show me what the news page looks like now" before publishing.
  3. Ask it to publish. Say the prompt below. Within about a minute the change appears on the live site (you may need a hard refresh: Cmd+Shift+R on Mac, Ctrl+F5 on Windows).
Say this to publish

Looks good — please commit and push this so it goes live.

✦

You can make several changes before publishing. Do them all, preview, then publish once at the end.

Section 04

Copy-paste recipes

Copy a prompt, paste it into Claude Code, and fill in the [bracketed] parts. Claude Code already knows the site's structure, so you don't have to.

Add a news item

Prompt

Add a news item to the website. Date: [e.g. July 15, 2026]. Text: '[the announcement, exactly as it should appear]'. Put it at the top of the correct year on the News page, and also add it to the Recent News section on the homepage (keep that list to the 4 newest). Then show me before publishing.

Add a new lab member

Prompt

On the People page, add a new current lab member. Name: [full name]. Role: [e.g. Graduate Student]. Email: [address, or 'none']. Bio: '[paste bio, or 'none']'. Their photo is the file I put in the images/people folder called [filename]. Add them to the site search too. Show me before publishing.

Move someone to "Former" members

Prompt

Move [name] from Current to Former Laboratory Members on the People page. Their destination is: '[e.g. Postdoctoral Fellow, Smith Lab, Yale University]'. Update the search entry too.

Add a publication

Prompt

Add a publication to the Publications page under [year, or 'Preprints']. Authors: [list — put lab members in bold]. Title: '[title]'. Journal: '[journal, volume, pages, year]'. Link: [DOI or URL]. The PDF is in the pdfs folder as [filename] (or: no PDF). Add it to the site search too. Show me before publishing.

Update Rachel's CV

Save the new CV as Carmody_CV.pdf, put it in the docs folder (replacing the old one — keep the same filename), then:

Prompt

Replace the CV on the site with the new Carmody_CV.pdf I put in the docs folder, then publish.

Fix a typo or reword something

Prompt

On the [page name] page, change the text '[current wording]' to '[new wording]'.

Section 05

Adding photos & files

Some changes need a file (a photo, a PDF) added first. Two ways:

  • Easiest: tell Claude Code where the file is and let it move it — "There's a photo on my Desktop called headshot.jpg — please add it as the photo for Jane Doe."
  • Manual: drag the file into the right folder yourself, then tell Claude Code it's there:
File typeGoes in this folder
images/people/Person headshots (square-ish, at least 600px)
pdfs/Publication PDFs
docs/The CV — name it Carmody_CV.pdf
images/Homepage slideshow images

Section 07

If something goes wrong

Nothing here is permanent — GitHub keeps a full history, so any change can be undone.

A change looks wrong on the live site

Prompt

Undo the last change and publish the fix.

You want to go back to how the site was before today

Prompt

Please revert the site to the last commit from before today's changes and push it.

The site didn't update after ~5 minutes

First do a hard refresh (Cmd+Shift+R / Ctrl+F5). If it's still stale:

Prompt

Did my last change actually get pushed to GitHub? Please check and push it if not.

Claude Code seems confused, or you're unsure

Prompt

Explain in simple terms what you're about to change, and don't publish anything yet.

✦
